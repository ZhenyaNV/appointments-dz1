# ДЗ1 — запись на приём к специалисту

Вариант 3. Евгений Невокшенов, БИСТ-24-ПО-1. Сервис хранит расписание, бронирует приём без пересечений, отменяет записи и считает загрузку специалистов и долю отмен.

## Содержание работы

Реализованы веб-интерфейс и 11 операций API: авторизация, просмотр справочников и свободных слотов, создание и отмена записи, просмотр списка и карточки, сводка загрузки. Подготовлены два воспроизводимых набора данных, 33 автоматических теста и измерения производительности.

## Запуск в Windows

1. Установите и запустите Docker Desktop с поддержкой Linux-контейнеров. При первом запуске нужен интернет для загрузки образов и зависимостей.
2. Скачайте проект или клонируйте репозиторий. Откройте PowerShell в папке, содержащей `compose.yaml` и `Dockerfile`.
3. Выполните:

```powershell
docker compose up -d --build --wait
```

4. Откройте http://localhost:8083. Вход: **demo / demo12345**.

Схема и малое наполнение создаются автоматически при первом запуске пустой базы. Повторный запуск сохраняет данные.

Рабочее расписание начинается 1 октября 2026 года. На малом наполнении оно занимает около недели; поиск свободных слотов по умолчанию использует 1–7 октября. Новая запись отображается в «Все записи», карточка открывается кнопкой «Открыть». Отмена сохраняет строку с новым статусом.

## Требования и технологии

Docker Desktop с Docker Compose v2 (`--wait`), минимум 4 ГБ доступной памяти. Отдельные Python, PostgreSQL или Node.js на машине не нужны. Контейнер: Python 3.12.10, FastAPI 0.115.12, uvicorn 0.34.2, psycopg 3.2.9. PostgreSQL 16.5 (образ закреплён по digest); точная версия образа и полный набор Python-зависимостей в `results/measurements.json` и `requirements.lock.txt`.

## Остановка

```powershell
docker compose stop
```

Данные сохраняются. Команда `docker compose down -v` удаляет том базы вместе с данными.

## Переменные окружения

Настройки необязательны. Для изменения создайте `.env` до первого запуска:

```powershell
Copy-Item .env.example .env
```

| Переменная | Назначение | По умолчанию |
|---|---|---|
| APP_PORT | Локальный порт интерфейса | 8083 |
| DB_PASSWORD | Пароль локальной PostgreSQL | local-study-password |
| DEMO_PASSWORD | Пароль демо-пользователя при наполнении | demo12345 |

Внутри контейнера DATABASE_URL задаёт соединение, DB_SCHEMA — `evgenii_nevokshenov`. PostgreSQL не публикует порт на компьютере; сервер публикуется только на 127.0.0.1. После создания тома изменение DB_PASSWORD в .env само по себе не меняет пароль PostgreSQL. DEMO_PASSWORD применяется при наполнении пустой БД или явном сбросе. Не публикуйте собственный .env.

## Наполнение

Обычный запуск создаёт малый набор: 10 специалистов, 10 услуг, 500 слотов, 300 записей. Рабочий: 200 специалистов, 30 услуг, 200000 слотов, 60000 записей. Данные синтетические, даты и генерация фиксированы, 20% исходных записей отменены.

Следующие команды **заменяют данные приложения**, включая вручную созданные записи:

```powershell
docker compose exec app python -m scripts.seed --size small --reset
```

```powershell
docker compose exec app python -m scripts.seed --size work --reset
```

После смены наполнения войдите заново. Команда без `--reset` сохраняет существующие данные. Команда выводит количества и контрольные суммы четырёх предметных таблиц.

## Тесты

Тесты бизнес-правил, API, конкурентного бронирования, воспроизводимости наполнения и расчёта измерений запускаются одним pytest. Используется отдельная база `evgenii_nevokshenov_test`; основная БД не изменяется. После запуска проекта выполните:

```powershell
docker compose exec db psql -U app -d postgres -c "CREATE DATABASE evgenii_nevokshenov_test"
docker compose run --rm -e DATABASE_URL=postgresql://app:local-study-password@db:5432/evgenii_nevokshenov_test app python -m pytest -q
```

Первую команду создания БД выполняют один раз; если база уже существует, переходят ко второй. При собственном пароле подставьте его в DATABASE_URL.

## Измерения

```powershell
docker compose exec app python -m scripts.benchmark
```

Скрипт использует отдельную `evgenii_nevokshenov_measure`; основная БД и вручную созданные записи не сбрасываются. В исследовательской БД данные заменяются. Последовательно загружаются и проверяются на воспроизводимость оба набора, снимаются 5 прогревочных и 30 измеряемых запросов всех 11 операций. При ошибке запроса серия прерывается, ошибка не превращается в удачный результат.

Результат: `results/measurements.json` — условия, версии, сырые времена, p50/p95/максимум, SQL-время и количество запросов. HTTP измеряется внутри контейнера по loopback, это фиксированное условие стенда. Между запросами нет искусственных задержек. Никакое кеширование не включено; прогрев учитывает обычный прогрев процесса и буферов PostgreSQL.

Для записи готовятся 70 дополнительных слотов и 35 записей для отмены; прогрев и серия создания добавляют ещё 35 записей. Итог: 370/60070 записей и 570/200070 слотов. Эти изменения отражены в JSON. У чтений набор данных одинаково подготовлен; к моменту сводки присутствуют 35 подготовленных записей отмены.

Число повторов можно изменить (не менее 20):

```powershell
docker compose exec app python -m scripts.benchmark --warmup 5 --repeats 50
```

## Если не запускается

Проверьте, что Docker Desktop открыт. Диагностика:

```powershell
docker compose ps
docker compose logs --tail=50 app
```

Если порт 8083 занят, задайте APP_PORT=8084 в `.env` и повторите запуск. Контейнеры и том используют персональное имя проекта и не управляют другими Docker-проектами на компьютере.
